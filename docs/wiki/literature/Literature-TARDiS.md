# TARDiS: ветка как механизм хранилища

Раздел: [Научная литература](Literature.md).

**Работа:** Crooks N., Pu Y., Estrada N., Gupta T., Alvisi L., Clement A. TARDiS: A Branch-and-Merge Approach To Weak Consistency. SIGMOD 2016, с. 1615–1628. [DOI: 10.1145/2882903.2882951](https://doi.org/10.1145/2882903.2882951) [[1]](#source-1).

**Направление Duro:** создание независимого варианта объекта, отложенное слияние.

**Зачем читать:** это ближайшая к Duro система, в которой ветка состояния является понятием самого хранилища, а не приёмом приложения.

## О чём работа

TARDiS – транзакционное хранилище со слабой согласованностью для геораспределённых приложений. Вместо разрешения конфликта при записи оно ветвится: при обнаружении конфликтующих операций состояние логически расходится, и обе ветви хранятся явно. История становится направленным ациклическим графом состояний.

Приложение получает две гарантии. Поток исполнения, продолжающий одну ветвь, видит хранилище последовательным. Слияние ветвей выполняет прикладной код и фиксирует его атомарно; хранилище предоставляет для этого точку расхождения и сведения о конфликтующих изменениях.

По оценке авторов, аккуратное применение branch-on-conflict повышает локальную пропускную способность на узле в два – восемь раз. Это их измерения на собственных приложениях, а не независимо воспроизведённый результат; к сценарию Duro они не переносятся напрямую.

## Что применимо к Duro

| Решение TARDiS | Отношение к модели Duro |
| --- | --- |
| Ветка принадлежит хранилищу, а не приложению | Совпадает: `fork` – операция платформы ([история и ветки](../concepts/Concepts-History.md)) |
| Ветка возникает автоматически при конфликте | Отличается: в Duro ветку создаёт явный вызов с заранее выбранным ID объекта |
| Общий DAG версий, ветви внутри одного хранилища | Отличается: ветка Duro – отдельный объект с собственной нумерацией от `0` |
| Слияние с данными о точке расхождения и конфликте | Отложено в Duro; работа показывает минимальный набор сведений, который для слияния нужен |
| Последовательность в пределах одной ветви | Совпадает с очередью одного объекта по [NFR-01](../requirements/nonfunctional/NFR-01.md) |

Для отложенной операции слияния работа задаёт проверяемое требование: платформа обязана сохранять точку расхождения ветви. Сейчас происхождение ветки хранится как ссылка `origin`, а предыстория остаётся у исходного объекта.

## Границы применимости

TARDiS решает задачу доступности при географической репликации: ветвление там – способ не блокировать запись при конфликте. В Duro ветка нужна разработчику и пользователю приложения для сравнения вариантов, и конфликта при её создании нет. Совпадает механизм, но не мотивация.

Хранение общего DAG даёт дешёвое ветвление, но связывает ветви общим хранилищем и требует сборки мусора старых ветвей. Duro в первом варианте выбирает копирование данных и независимость объектов; основания приведены в [альтернативах](../concepts/Concepts-Alternatives.md#требования-к-снимкам-данных). Работа полезна как описание цены противоположного выбора.

Ветвится в TARDiS хранилище, а не объект с поведением. Прикладной код у ветви тот же; версия кода, зафиксированная на ревизии, в модели отсутствует.
