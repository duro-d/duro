# Хранение и восстановление Durable Objects

После перезапуска DO получает данные, которые приложение явно записало через Storage API. Поля класса остаются в рабочей памяти и могут исчезнуть при выгрузке, сбое или обновлении кода [[1]](#source-1).

Storage API предоставляет транзакционное строго согласованное хранилище в пределах объекта: после подтверждения записи последующее чтение не получает устаревшее значение из отставшей реплики. Согласование с другими объектами и внешними системами требует отдельного протокола [[1]](#source-1).

## Хранилище и память экземпляра

| Данные | Как переживают перезапуск |
| --- | --- |
| `this.total`, локальные переменные, кеш | Приложение восстанавливает их из сохранённых данных |
| Значение, прочитанное через `get` и изменённое в памяти | Требуется явная запись изменённого значения |
| Записи через Storage API | После подтверждения доступны следующему экземпляру |
| Стек метода и незавершённый `Promise` | Не входят в сохранённые пользовательские данные |

Например, метод загрузил план, добавил расход в локальный массив и вернул ответ. Если он не записал изменённый план, следующий экземпляр увидит прежние данные. Разработчик сам выбирает, какие значения сохранять и какие использовать только для текущих вычислений [[2]](#source-2).

Пусть в storage уже сохранено `total = 0`. Два варианта изменения дают разные результаты после выгрузки:

```javascript
// Вариант A: меняется только поле экземпляра
this.total = 200;
// Новый экземпляр прочитает из storage прежнее значение 0.

// Вариант B: приложение сохраняет значение
await storage.put("total", 200);
// После подтверждения записи и выгрузки экземпляра:
const total = await storage.get("total"); // 200
```

`storage` здесь означает хранилище одного DO. Код показывает два независимых запуска с одинаковыми начальными данными. Загрузка полей из storage при создании экземпляра остаётся задачей приложения.

## SQLite и KV

Для новых классов Cloudflare рекомендует SQLite. SQL-хранилище стало общедоступным 7 апреля 2025 года. Старый движок KV сохраняется для совместимости. KV API есть и у объектов с SQLite, поэтому название интерфейса ещё не определяет движок хранения [[3]](#source-3).

В DO с SQLite доступны SQL, KV, alarms и PITR. SQL вызывается через `ctx.storage.sql.exec(...)`, а KV позволяет работать с ключами и значениями. Хранилище приватно для объекта: соседний DO не открывает его таблицы напрямую [[1]](#source-1).

В старых примерах KV может означать движок с другими лимитами. Перед использованием такого примера стоит проверить тип хранилища.

## Совместное размещение кода и БД

SQLite работает как библиотека в том же потоке, что и прикладной код объекта. Для выполнения SQL-запроса не нужен отдельный сетевой вызов к серверу БД. API возвращает результат синхронно. Это особенно полезно, когда метод делает несколько небольших зависимых чтений [[4]](#source-4).

После локального выполнения запроса запись ещё должна получить долговечное подтверждение. Runtime использует output gates, чтобы задержать исходящий результат до этого подтверждения. Подробнее о них на странице [конкурентности и гарантий](Durable-Objects-Coordination.md).

## Добавление расхода с проверкой бюджета

В одном объекте можно проверить общий бюджет и сохранить расход в транзакции. В примере на JavaScript используются синхронные SQL-запросы: `SQL(...)` вызывает `storage.sql.exec(...)`. Таблица `plan` содержит одну запись с бюджетом, а `expenses` хранит расходы объекта. Для отката при исключении используется `transactionSync` [[5]](#source-5).

```javascript
function addExpense(id, amount) {
    if (!(amount >= 0)) {
        throw new Error("InvalidAmount");
    }

    const SQL = (query, ...params) => storage.sql.exec(query, ...params);

    return storage.transactionSync(() => {
        const budget = SQL("SELECT budget FROM plan").one().budget;
        const total = SQL("SELECT COALESCE(SUM(amount), 0) AS total FROM expenses")
            .one().total;

        if (total + amount > budget) {
            throw new Error("BudgetExceeded");
        }

        SQL("INSERT INTO expenses (id, amount) VALUES (?, ?)", id, amount);
        return { total: total + amount };
    });
}
```

При бюджете `1000` и начальной сумме расходов `700` последовательные вызовы дадут такой результат. Суммы целые, в условных единицах; ID новых расходов ещё не заняты.

| Вызов | Сумма до | Результат | Сумма после |
| --- | --- | --- | --- |
| `addExpense("taxi", 200)` | 700 | Расход сохранён | 900 |
| `addExpense("museum", 400)` | 900 | Ошибка превышения бюджета | 900 |

В callback нет внешних сетевых вызовов и `await`. Проверка и запись выполняются в одной транзакции. Отправку уведомления после добавления расхода пришлось бы согласовывать отдельно.

## Восстановление после отказа

В публикации 2024 года Cloudflare описывает Storage Relay Service: изменения SQLite передаются репликам и сохраняются в объектное хранилище, а снимки сокращают объём воспроизведения. Подтверждение записи зависит и от реплик, поэтому отказ локального диска исполнителя не означает потерю подтверждённых данных. SRS описывает внутреннее устройство системы на момент публикации; API приложения не закрепляет конкретную схему репликации [[4]](#source-4).

Журнал хранения позволяет восстановить содержимое БД. Чтобы объяснить, кто добавил расход и зачем, приложению нужны собственные предметные сведения. Физическое изменение страниц SQLite само по себе не задаёт событие `ExpenseAdded`.

## Восстановление на момент времени (PITR)

PITR позволяет восстановить SQL- и KV-данные объекта с SQLite в пределах последних 30 дней. Точка обозначается bookmark. `getBookmarkForTime(...)` находит приблизительную точку по времени, а `onNextSessionRestoreBookmark(...)` назначает восстановление при следующем перезапуске объекта. После этого `ctx.abort()` используют для перезапуска [[6]](#source-6).

Это восстановление текущей БД исходного объекта. Вызов не возвращает независимый исторический экземпляр для параллельной работы. Изменение содержимого БД также не отменяет уже выполненные внешние действия. Различия с пользовательской историей и ветвлением разобраны в [сравнении с Duro](Durable-Objects-and-Duro.md).
