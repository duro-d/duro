# Сценарии использования

Сценарии демонстрируют объектный API, highload и восстановление. Основной тип – [аукцион](concepts/Concepts-Auction.md), второй – квота. Приложение проверяет предметные правила, Duro обеспечивает исполнение и сохранение.

## UC-01. Подключить тип и создать объект

Разработчик собирает JavaScript bundle, загружает его с манифестом и создаёт объект по выбранному ID. Исполнитель запускает `init`, сохраняет начальные данные и возвращает результат. Пакет доступен нодам с пустым кешем. Подключение второго типа не требует пересборки серверов.

Требования: [FR-01](requirements/functional/FR-01.md), [FR-02](requirements/functional/FR-02.md).

## UC-02. Вызвать метод объекта

Два клиента делают ставки в одном аукционе. Методы выполняются по очереди; второй проверяет актуальную подтверждённую ставку. Успех означает фиксацию состояния и результата. Если ответ потерян, повтор с тем же ID возвращает прежний ответ. Ошибка после `put` не оставляет частичных изменений.

Требования: [FR-04](requirements/functional/FR-04.md), [NFR-01](requirements/nonfunctional/NFR-01.md).

## UC-03. Прочитать текущие данные

Клиент запрашивает состояние. Получает целиком подтверждённую версию. При недоступности хранения старый кеш не выдаётся за текущее состояние. Предметное представление можно получить через читающий метод с новым `request_id`.

Требования: [FR-03](requirements/functional/FR-03.md), [FR-05](requirements/functional/FR-05.md).

## UC-04. Восстановить обслуживание после отказа

Во время запросов оператор останавливает рабочую ноду. Duro обнаруживает отказ, передаёт владение и загружает данные на другой ноде. Клиент продолжает обращаться к тому же ID и повторяет неподтверждённый запрос. Проверяются сохранность, отсутствие дублей и отказ в записи прежнему владельцу.

Отдельно останавливается primary PostgreSQL, затем в полном стенде – одна VM. После автоматического переключения выполняется изменяющая команда. Проверяется не только доступность чтения, но и восстановление исполнения и записи.

Требования: [FR-09](requirements/functional/FR-09.md), [NFR-02](requirements/nonfunctional/NFR-02.md).

## UC-05. Сравнить размещение под нагрузкой

Генератор обращается к большому числу объектов сначала равномерно, затем с перекосом популярности. Один и тот же набор запросов и параметры стенда используются для хеширования и размещения по нагрузке. Измеряются успешные операции/с, p95/p99, ошибки и дисбаланс. Прогоны повторяются с разным числом исполнителей.

Требования: [FR-06](requirements/functional/FR-06.md), [NFR-05](requirements/nonfunctional/NFR-05.md).

## UC-06. Добавить ноду и перенести объекты

Оператор запускает дополнительного исполнителя. Контроллер выбирает объекты для переноса. Новые вызовы временно задерживаются или получают повторяемую ошибку; текущий метод заканчивается, владение меняется, состояние загружается на новой ноде. Генератор продолжает работу. Проверяются сохранность, время паузы и изменение загрузки.

Требования: [FR-07](requirements/functional/FR-07.md).

## UC-07. Пережить перегрузку

Генератор увеличивает поток к небольшой группе объектов выше возможностей их обработки. Очереди и память остаются ограниченными. Новые вызовы получают `OVERLOADED`, а остальные объекты продолжают обслуживаться в пределах доступных ресурсов. После снижения потока система возвращается к обычной работе.

Требования: [FR-08](requirements/functional/FR-08.md), [NFR-04](requirements/nonfunctional/NFR-04.md).

## UC-08. Наблюдать демонстрацию

Клиент показывает ставки или расход квоты, Grafana – нагрузку, очереди, отказы и переносы. Скрипт воспроизводит нагрузку и остановки. Отчёт содержит конфигурацию, исходные замеры и проверку подтверждённых операций.

Требования: [FR-10](requirements/functional/FR-10.md), [NFR-08](requirements/nonfunctional/NFR-08.md).
