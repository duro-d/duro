# Исполнение и восстановление

Рабочая нода – Rust-процесс с V8 через `deno_core`. Она обслуживает много объектов, выполняет загруженные JavaScript-методы и управляет очередями и памятью.

## Активация

Для объекта нода получает пакет закреплённой версии, проверяет хеш и загружает сохранённые данные. Код и подтверждённые данные кешируются в пределах заданных бюджетов. При выгрузке экземпляра долговечное состояние остаётся в БД.

Успешное создание фиксируется один раз. Исполнение `init` до commit может повториться. После успешного создания активация не вызывает прикладную инициализацию повторно.

## Владение

Назначение хранит ID ноды, поколение и срок аренды. Его выбирает маршрутизация, а модуль состояния проверяет право записи. Новое владение выдаётся с новым поколением; подтверждение старого поколения отклоняется.

Событие недоступности в etcd не заменяет этот протокол. Проверка владения и изменение данных выполняются атомарно в PostgreSQL. При отсутствии надёжного подтверждения операции приостанавливаются.

## Восстановление данных и повтор метода

После отказа контроллер передаёт владение доступной ноде. Она загружает код и текущее подтверждённое состояние. Клиент продолжает использовать прежний ID.

Операция с потерянным ответом проверяется по `request_id`. Если она зафиксирована, возвращается сохранённый ответ; иначе допустимо новое исполнение. Незавершённый стек V8 не продолжается, очередь в памяти старой ноды не восстанавливается. Клиентский SDK повторяет неподтверждённые вызовы.

## Перенос под нагрузкой

При управляемом переносе старый владелец завершает текущую операцию, затем право записи передаётся новому. Целевая нода загружает состояние, кеши маршрутов обновляются. Во время перехода допустима краткая недоступность с повтором прежнего запроса.

Стоимость переноса включает паузу, загрузку данных и прогрев. Контроллер ограничивает частоту переносов; увеличение числа нод само по себе не означает мгновенное перемещение всех объектов.

## Ограничения выполнения методов

Методы одного объекта выполняются последовательно, разных объектов – параллельно в пределах ресурсов. Платформа ждёт завершения Promise, ограничивает время, очереди и память. После ошибки контекст с неподтверждёнными изменениями не используется следующим методом.

Механизм потоков, isolates и прерывания описывается в модуле исполнения. Контракт требует, чтобы таймаут запрещал позднюю фиксацию и не оставлял состояние повреждённым.

## Внешние действия

В MVP обработчик получает стандартный JavaScript и контекст Duro. Сеть, файловая система, таймеры, фоновые задачи и вызовы других объектов не предоставляются. Приложение выполняет внешнюю работу вне метода; атомарность с ней Duro не обещает.

Полный формат пакета и Storage API – в [технических решениях](../Technical-Decisions.md).
