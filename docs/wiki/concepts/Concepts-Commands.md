# Команды и повторы

Команда — `create` или вызов метода с `request_id`. Один метод получает JSON-аргумент, работает с состоянием текущего объекта и возвращает JSON-значение либо завершается без значения.

## Исполнение метода

1. Проверить завершённый результат запроса.
2. Для новой операции выполнить метод в очереди владельца.
3. Дождаться Promise, сериализовать результат и подготовленные записи.
4. Атомарно проверить полномочия и сохранить данные с результатом.
5. После долговечного подтверждения вернуть `{ result, revision }`.

Отсутствующий аргумент обозначается `null`. Отсутствующее возвращаемое значение становится `result: null`. Неподдерживаемое значение или ошибка сериализации не приводят к частичной записи.

## Ревизия

Создание получает ревизию `0`. Успешный метод с записями увеличивает её на один, в том числе при записи прежнего значения. Без записей и при предметном отказе ревизия не меняется. Она проверяется внутри платформы и помогает обнаруживать устаревшее состояние исполнителя; клиент не передаёт ожидаемую ревизию.

Ревизия является техническим номером. API открытия прошлой версии нет.

## Повтор запроса

Клиент сохраняет `request_id` до отправки. После таймаута или потери ответа повторяет те же параметры с тем же ID. Область уникальности — `(object_id, request_id)`. Иная операция под тем же ID получает `REQUEST_ID_CONFLICT`.

Завершённый повтор возвращает прежний результат, включая предметный отказ. Метод без записей также запоминается: новый запрос актуального представления требует нового ID. Одновременные повторы могут начать исполнение, но не могут дважды зафиксировать изменение.

SDK выполняет ограниченные повторы технических ошибок с задержкой и общим deadline. Предметный отказ не повторяется как новая операция. После исчерпания времени клиент сохраняет ID: истечение deadline не доказывает отмену.

Если исход commit неизвестен, платформа проверяет результат и его долговечность. До разрешения исхода объект не продолжает работу на предположительно сохранённом состоянии.

## Ошибки и чтения

`ctx.reject(message)` завершает метод с `DOMAIN_REJECTED`, отбрасывает записи и сохраняет отказ. Внутреннее исключение, таймаут и ошибка сериализации отбрасывают буфер, но сами не становятся завершённым прикладным результатом.

`read` получает текущее состояние с primary через модуль хранения. Читающий RPC выполняется по обычным правилам и сохраняет свой результат. Ошибки API перечислены в [функциональных требованиях](../Functional-Requirements.md#ошибки).
