# Альтернативы и проверка гипотезы

Рабочая гипотеза: разработчику полезен объектный API, который объединяет размещение, исполнение, долговечное состояние и восстановление при высокой неравномерной нагрузке. Её проверяем на аукционах и квотах и на воспроизводимых нагрузочных профилях.

## Базовые подходы

| Подход | Что даёт | Что исследуем в Duro |
| --- | --- | --- |
| Сервис и PostgreSQL | Транзакции и привычная разработка приложения | Удобство отдельного объектного API и стоимость управления размещением |
| Cloudflare Durable Objects | Адресуемые объекты с кодом и состоянием | Собственное развёртывание, контролируемый стенд и изменяемые алгоритмы размещения |
| Orleans | Виртуальные акторы, активация и политики размещения | Поведение своих политик при выбранных workload и гарантиях хранения |
| Rust + V8 + PostgreSQL | Выбранная основа MVP | Интеграция трёх модулей и измеряемое масштабирование |

Ориентиры: [Durable Objects](https://developers.cloudflare.com/durable-objects/), [размещение Orleans](https://learn.microsoft.com/en-us/dotnet/orleans/grains/grain-placement), [транзакции PostgreSQL](https://www.postgresql.org/docs/18/tutorial-transactions.html).

Наличие платформы не гарантирует преимущества над обычным сервисом. Первый управляемый эксперимент – сравнение политик внутри Duro при одинаковых ресурсах и гарантиях. Сравнение с внешними продуктами требует отдельно согласованного стенда и не является обязательным результатом MVP.

## Выбор исполнения и хранения

JavaScript на V8 позволяет сохранить загрузку кода без разработки своего языка или компилятора. Rust-нода встраивает готовый `deno_core`; приложение заранее собирает bundle. Полный Deno или Node.js API не требуется.

PostgreSQL выбран для атомарного сохранения состояния и результата с проверкой владельца. Patroni и синхронная репликация дают основу испытаний отказа хранения. Redis Cluster не выбран из-за допускаемой потери подтверждённых записей при отказах. Подробности и первоисточники – в [технических решениях](../Technical-Decisions.md).

## Границы сравнения

Измеряем успешную пропускную способность вместе с p99, техническими ошибками и стоимостью восстановления. Подтверждение из памяти не сравнивается с долговечной фиксацией как равнозначная операция. Перенос популярного объекта не считается распараллеливанием его последовательной логики.

Пользовательское версионирование, CRDT, геораспределение, межобъектные транзакции и изоляция недоверенных приложений находятся вне MVP. Полный перечень – в [требованиях](../Requirements.md).
