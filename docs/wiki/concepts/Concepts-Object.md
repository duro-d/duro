# Модель объекта

Объект имеет постоянный `object_id`, тип, версию кода, набор методов и собственное KV-состояние. Адрес рабочей ноды не является частью ID. Объект сохраняется при смене исполнителя и не обязан постоянно занимать память.

## Тип и код

Разработчик загружает самодостаточный JavaScript ES module bundle. Он экспортирует `init(ctx, input)` и `methods`. Пакет сохраняется в Duro, а Rust-исполнители загружают его в V8 через `deno_core`.

`registerType` регистрирует код, `create` создаёт объект, `invoke` вызывает метод. Неизвестный ID не создаётся автоматически. Версия кода фиксируется при создании и сохраняется при восстановлении и переносе. Один пакет обслуживает множество объектов.

## Данные и память

Долговечные данные доступны через `ctx.storage.get/put/delete`. Поля JavaScript и глобальные переменные временные; после выгрузки или сбоя они могут исчезнуть. Бизнес-логика не должна полагаться на их сохранение между вызовами.

Каждый метод работает только с текущим объектом. Операции других объектов и внешние действия из обработчика не входят в MVP. JSON-значения возвращаются копиями; для сохранения изменения нужен `put`.

## Порядок и жизненный цикл

Один владелец последовательно обрабатывает методы объекта. Разные объекты работают параллельно. При смене владельца прежний процесс ещё может существовать, но модуль состояния запрещает ему фиксацию с устаревшим поколением.

`init` задаёт начальные данные. После успешного создания восстановление загружает подтверждённые значения без повторной инициализации. Незавершённый вызов повторяется с прежним `request_id`; стек метода не переносится.

Пример объекта – [аукцион](Concepts-Auction.md). Размещение множества объектов разобрано в [highload-модели](Concepts-Highload.md).
