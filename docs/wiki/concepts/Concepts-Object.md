# Модель объекта

**Объект в Duro – экземпляр пользовательского типа с постоянным идентификатором, собственным долговечным состоянием и набором методов его обработки.** Вызовы методов одного объекта выполняются последовательно. Идентификатор и подтверждённое состояние сохраняются при смене исполнителя; постоянное нахождение объекта в памяти не требуется.

В MVP объект является границей обработки и атомарного изменения состояния: его методы работают только с состоянием этого объекта. Они не могут вызывать методы других объектов, читать или изменять их состояние и выполнять внешние сетевые операции. Атомарные операции над несколькими объектами не поддерживаются. Версия кода фиксируется при создании объекта.

Идентификаторы других объектов могут храниться как обычные данные, но платформа не предоставляет разыменование таких ссылок или межобъектные вызовы. Если сценарий затрагивает несколько объектов, отдельные обращения к ним организует внешний клиент. Эти обращения не образуют общей транзакции.

## Идентичность и граница объекта

`object_id` обозначает конкретный объект и не содержит адрес рабочей ноды. Два объекта с одинаковым состоянием и кодом остаются разными объектами, если у них разные ID. Перенос, восстановление или выгрузка из памяти не создают новый логический объект.

Разработчик выбирает, какая сущность приложения соответствует одному объекту. Данные, которые требуется проверять и изменять атомарно одним методом, должны находиться в состоянии одного объекта. Вложенное JSON-значение не становится отдельным объектом Duro: для отдельного объекта нужны собственный `object_id` и создание через `create`.

## Тип и код

Тип задаёт код и доступные методы; объект является конкретным экземпляром этого типа со своим ID и состоянием. Разработчик загружает самодостаточный JavaScript ES module bundle. Он экспортирует `init(ctx, input)` и `methods`. Пакет сохраняется в Duro, а Rust-исполнители загружают его в V8 через `deno_core`.

`registerType` регистрирует код, `create` создаёт объект, `invoke` вызывает метод. Неизвестный ID не создаётся автоматически. Версия кода фиксируется при создании и сохраняется при восстановлении и переносе. Один пакет обслуживает множество объектов.

## Данные и память

Долговечные данные доступны через `ctx.storage.get/put/delete`. Поля JavaScript и глобальные переменные временные; после выгрузки или сбоя они могут исчезнуть. Бизнес-логика не должна полагаться на их сохранение между вызовами.

`ctx.storage` обращается только к KV-состоянию текущего объекта. JSON-значения возвращаются копиями; для сохранения изменения нужен `put`. Вложенные структуры и сохранённые ID других объектов остаются обычными JSON-данными.

Ограничения доступа действуют и для `init`. Среда обработчика не предоставляет сеть, файловую систему, фоновые задачи, таймеры или клиентский API Duro. Состав контекста и формат пакета описаны в [технических решениях](../Technical-Decisions.md#какие-возможности-среды-доступны).

## Порядок и жизненный цикл

Один владелец последовательно обрабатывает методы объекта. Разные объекты работают параллельно. При смене владельца прежний процесс ещё может существовать, но модуль состояния запрещает ему фиксацию с устаревшим поколением.

`init` задаёт начальные данные. После успешного создания восстановление загружает подтверждённые значения без повторной инициализации. Незавершённый вызов повторяется с прежним `request_id`; стек метода не переносится.

## Пример: один аукцион

`Auction` – тип, а `auction:42` – объект этого типа. Его состояние содержит текущую цену, участника с лучшей ставкой и признак закрытия. Методы `bid`, `close` и `getSummary` определяют поведение. Объект `auction:43` использует тот же код, но имеет собственное состояние.

Аукцион может хранить ID участника или его кошелька. Метод `bid` в MVP не может вызвать объект кошелька или списать деньги из его состояния. Внешний клиент может отдельно вызвать оба объекта, но Duro не гарантирует атомарность ставки и списания вместе.

Пакет и вызовы клиента приведены в [примере аукциона](Concepts-Auction.md). Размещение множества объектов разобрано в [highload-модели](Concepts-Highload.md).
