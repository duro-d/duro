# Модель объекта

Объект Duro объединяет постоянный ID, прикладные методы и собственное хранилище. В примере один объект содержит план поездки: лимит бюджета и список расходов.

## Идентичность и тип

| Свойство | Назначение |
| --- | --- |
| `object_id` | Адрес логической сущности |
| `type` | Набор методов и правила работы с данными |
| `code_version` | Версия прикладного кода |
| `revision` | Текущая подтверждённая ревизия данных |
| `origin` | Для ветки: ID источника и исходная ревизия |

В PoC ID уникален в пределах развёртывания Duro, которое обслуживает одно доверенное приложение. Адресация нескольких приложений относится к дальнейшему развитию.

Смена исполнителя сохраняет ID объекта и его данные. Duro создаёт новый экземпляр прикладного кода и даёт ему доступ к подтверждённому хранилищу. Разработчик может загрузить нужные значения в рабочую память или читать их через `storage` по мере обращения.

В PoC версия кода фиксируется при создании объекта. Операция `updateCode` не входит в MVP. При её выполнении Duro ждёт завершения предыдущего метода, запускает `migrate` новой версии и сохраняет код с преобразованными данными одной ревизией. При неудачном преобразовании прежние код и данные сохраняются. Ветки автоматически не обновляются.

## Хранилище и рабочая память

| Где находятся данные | Что нужно для сохранения после сбоя |
| --- | --- |
| Поле экземпляра или локальная переменная | Явная запись нужного значения в `storage` |
| Значение, прочитанное через `storage.get` | После изменения требуется `storage.put` |
| Подтверждённая запись в `storage` | Duro сохраняет её и журнал изменений |
| Кеш или вспомогательный индекс в памяти | Разработчик пересоздаёт его из хранимых данных |

Изменение поля `this.budget` само по себе не создаёт долговечной записи. Значение, полученное через `get`, разработчик меняет в рабочей памяти. Для сохранения этих правок нужно вызвать `put`.

Сокеты, файловые дескрипторы и стек метода не входят в версию объекта. Снимок в Duro означает образ хранимых данных; захват памяти процесса в модель не входит.

## Граница объекта

Один объект объединяет данные, которые нужно проверять и изменять в рамках одной команды.

В плане поездки добавление расхода требует прочитать бюджет и сумму существующих позиций. Метод проверяет новый итог и записывает список расходов. Эти данные находятся в одном хранилище и участвуют в одной границе фиксации.

Позиция расхода может иметь свой ID внутри плана. Duro при этом адресует весь план. Если вынести бюджет и расходы в разные распределённые объекты, потребуются правила согласования нескольких хранилищ.

Эта же граница действует при ветвлении: Duro создаёт новый объект из содержимого одного хранилища. Ссылки на другие объекты остаются ссылками. Копирование графа объектов пока не входит в контракт.

## Создание

Сначала разработчик загружает пакет типа и версии через `registerType`. Это регистрирует исполняемый код для повторного использования, без создания объекта. Затем клиент передаёт в `create` тип, версию, новый ID и входные данные. Метод инициализации проверяет вход и явно записывает начальные значения через `storage`. Например, бюджет и пустой список расходов.

Duro принимает создание вместе с начальными записями как ревизию `0`. Сохраняются только значения, переданные в хранилище. Автоматической сериализации всех полей экземпляра нет.

Клиент заранее выбирает ID объекта и стабильный ID запроса. Повтор завершённого создания возвращает прежний результат. Другой запрос создания на занятый ID означает конфликт.

## Ревизия, код и владение

Ревизия меняется при фиксации записей команды, а также при дополнительных операциях отката и обновления кода. Поколение владельца меняется при передаче полномочий исполнителю. Версия кода обозначает реализацию методов.

Перенос объекта не обязан менять ревизию. Откат данных создаёт новую ревизию, сохраняя текущую версию кода и сведения о владении. Ветка получает новый ID и начинает собственную нумерацию с `0`.

## Масштабирование

Разные планы и их ветки можно исполнять параллельно. Команды одного объекта образуют последовательность изменений его хранилища.

Добавление исполнителей позволяет распределять много объектов. Для PoC используются два исполнителя; автоматическое масштабирование отложено. Ограничения размера объекта, времени метода и очереди заданы в [NFR-04](../requirements/nonfunctional/NFR-04.md).
