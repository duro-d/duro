# FR-04. Вызвать RPC-метод

Раздел: [Функциональные требования](../../Functional-Requirements.md). Операция подчиняется [общим правилам](../../Functional-Requirements.md#общие-правила).

**Участник:** клиентское приложение.

**Вход:** `object_id`, имя метода `method`, один JSON-аргумент `argument` и `request_id`. Метод без входных данных получает `null`.

**Результат:** `{ result, revision }` после завершения и фиксации метода. `result` содержит JSON-значение либо `null`, если метод не возвращает значение. Даже в последнем случае клиент получает подтверждение выполнения.

**Порядок выполнения:**

1. Duro проверяет завершённый результат по `(object_id, request_id)` до выбора исполнителя и проверки текущей версии кода. Если параметры совпадают, возвращает его; другое содержимое даёт `REQUEST_ID_CONFLICT`.
2. Для нового запроса находит объект и исполнителя по ID, ставит вызов в очередь объекта. Клиент не передаёт адрес исполнителя; неизвестный объект автоматически не создаётся.
3. Когда очередь доходит до вызова, повторно проверяет сохранённый результат: за время ожидания другой повтор мог завершиться. Для новой операции проверяет наличие метода в закреплённой за объектом версии кода и при необходимости загружает её пакет.
4. Запускает метод с аргументом и хранилищем объекта, ждёт завершения обработчика и подготавливает JSON-результат.
5. При успешном завершении сохраняет все записи, историю и результат запроса одной транзакцией. Если записей нет, сохраняет только результат, а ревизия остаётся прежней.
6. Возвращает результат и ревизию.

Предметный отказ, внутреннее исключение и таймаут обрабатываются по общим правилам. Подготовленные записи не сохраняются. Предметный отказ запоминается для повторов без новой ревизии.

```javascript
await duro.invoke("trip/main", "addExpense", { id: "train", amount: 200 }, {
  request_id: "add-train"
});
// → { result: { total: 200 }, revision: 1 }

await duro.invoke("trip/main", "getSummary", null, { request_id: "summary-1" });
// → { result: { budget: 1000, total: 200 }, revision: 1 }
```

**Приёмка:** метод видит собственные `put` и `delete`. Изменение поля экземпляра или полученного значения без `put` не сохраняет данные. Два одновременных вызова одного объекта выполняются по очереди. Проверка бюджета во втором вызове учитывает результат первого. Ошибка после нескольких `put` не оставляет записей и не влияет на следующий вызов. Метод без возвращаемого значения получает подтверждение с `result: null`; ошибка сериализации не оставляет частичных изменений. Повтор с тем же `request_id` и параметрами возвращает прежний результат; одновременные повторы дают одну фиксацию. Новый `request_id` запускает метод заново, даже если имя и аргумент совпадают. Для свежего результата `getSummary` клиент также использует новый ID.
