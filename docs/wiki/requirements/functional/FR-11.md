# FR-11. Автоматически изменять активный пул исполнителей

Раздел: [Функциональные требования](../../Functional-Requirements.md).

**Статус:** опциональное расширение. Отсутствие этой возможности не блокирует приёмку MVP по FR-01–10 и NFR-01–10. В RFC маршрутизации и исполнения нужно оценить точки расширения; реализация и конкретные RPC для FR-11 могут быть отложены.

Контроллер может увеличивать и уменьшать число активных исполнителей из заранее подготовленного пула. Оператор задаёт минимальный и максимальный размер активного пула, пороги нагрузки, окно наблюдения и задержку между изменениями. Минимум не меньше одного; масштабирование до нуля не входит в расширение.

## Состав пула

| Режим | Назначение |
| --- | --- |
| Резерв | Нода подготовлена и доступна, но не получает назначения объектов |
| Активна | Может получать новые назначения и обслуживает свои объекты |
| Выводится | Не получает новых назначений; завершает принятые операции и передаёт объекты другим исполнителям |

Режим участия и фактическая доступность ноды учитываются отдельно. Недоступную резервную ноду нельзя считать готовой ёмкостью. При отказе во время вывода применяется обычный протокол [восстановления](FR-09.md).

При устойчивом росте нагрузки контроллер проверяет готовность резерва, включает доступную ноду в активный пул и размещает или переносит на неё объекты по [FR-06](FR-06.md) и [FR-07](FR-07.md). Пороги увеличения и уменьшения различаются; окно наблюдения и задержка между решениями защищают от постоянного переключения состава. Устаревшие метрики не должны приводить к уменьшению пула.

При снижении нагрузки контроллер сначала запрещает новые назначения на выбранную ноду. Вызовы её текущих объектов продолжают направляться действующему владельцу до завершения переноса. Нода возвращается в резерв после разрешения исходов принятых операций и передачи всех владений. Простое удаление ноды из маршрутов не заменяет этот протокол. При нехватке целевой ёмкости вывод откладывается.

## Границы и оценка результата

Расширение управляет участием подготовленных исполнителей. Создание VM, облачный autoscaling, остановка и запуск серверов требуют отдельной инфраструктурной интеграции и не входят в FR-11. Резервная работающая VM может продолжать потреблять ресурсы и оплачиваться; уменьшение активного пула само по себе не доказывает экономию. Полностью выведенный worker-процесс можно остановить внешним средством, а перед возвращением снова проверить его готовность.

Изменение пула исполнителей не меняет состав PostgreSQL, etcd и маршрутизаторов. Приёмка отказоустойчивости сохраняет состав стенда по [NFR-02](../nonfunctional/NFR-02.md) и [NFR-07](../nonfunctional/NFR-07.md). В сравнительных прогонах [NFR-05](../nonfunctional/NFR-05.md) автоматическое изменение пула отключено: число исполнителей фиксировано для каждого прогона.

**Приёмка расширения:** отдельный сценарий низкая нагрузка → устойчивый всплеск → снижение нагрузки. Проверяются включение доступного резерва, безопасный вывод после переноса, соблюдение минимума и максимума, отсутствие частых переключений при колебании нагрузки и отказ во время вывода. Подтверждённые данные не теряются, старый владелец не может фиксировать изменения. Отчёт содержит размер активного пула во времени, CPU/RAM, очередь, p99, ошибки, время подключения, паузу переноса и затраты на перемещение данных. Ускорение одного последовательного горячего объекта за счёт добавления нод не обещается.
