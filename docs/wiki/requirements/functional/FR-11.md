# FR-11. Восстановить объект после остановки исполнителя

Раздел: [Функциональные требования](../../Functional-Requirements.md). Операция подчиняется [общим правилам](../../Functional-Requirements.md#общие-правила).

**Участник:** платформа; оператор проверяет восстановление.

**Вход:** постоянный ID объекта и его сохранённые данные. Клиент продолжает обращаться к прежнему API.

**Результат:** объект обслуживается доступным исполнителем с прежними ID, данными и версией кода.

**Порядок выполнения:**

1. Duro обнаруживает остановку исполнителя.
2. Передаёт право записи другому исполнителю.
3. Загружает последние сохранённые данные и пакет зафиксированной версии кода, в том числе при пустом локальном кеше пакетов.
4. Создаёт экземпляр без повторного запуска инициализации.
5. Принимает новые обращения по прежнему ID. Старому исполнителю запись запрещена.

**Приёмка:** остановка до сохранения не оставляет частичных изменений. Остановка после сохранения не теряет данные и результат запроса, даже если ответ не дошёл до клиента. Повтор с прежним `request_id` получает этот результат без новых записей. Незавершённый вызов автоматически не запускается заново. Вернувшийся старый исполнитель не может записать изменения или выдать устаревший кеш за текущие данные. Восстановление подтверждается успешным изменяющим RPC-вызовом на другом исполнителе; одного чтения данных недостаточно.

Связанные сценарии: [UC-08](../../Use-Cases.md#uc-08-восстановить-обслуживание-после-отказа).
