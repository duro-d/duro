# FR-02. Создать объект

Раздел: [Функциональные требования](../../Functional-Requirements.md). Операция подчиняется [общим правилам](../../Functional-Requirements.md#общие-правила).

**Участник:** клиентское приложение.

**Вход:** `object_id`, тип, версия кода, начальные данные в JSON и `request_id`.

**Результат:** `object_id`, версия кода, ревизия `0` и JSON-результат инициализации.

Создание использует пакет, загруженный по FR-01. Код не нужно передавать заново для каждого объекта. Инициализация может завершиться без значения; тогда `result` равен `null`.

**Порядок выполнения:**

1. Duro проверяет `request_id` и возвращает результат завершённого создания, если он найден. Иначе проверяет, что ID свободен, а тип и версия зарегистрированы.
2. Запускает инициализацию с начальными данными и пустым хранилищем.
3. Сохраняет объект, его начальные данные, запись истории и результат запроса одной транзакцией.
4. Возвращает результат после сохранения.

```javascript
await duro.create({
  object_id: "trip/main",
  type: "TripPlan",
  code_version: "1",
  input: { budget: 1000 },
  request_id: "create-main"
});
// → { object_id: "trip/main", code_version: "1", revision: 0, result: null }
```

**Приёмка:** объект доступен по выбранному ID. Повтор с тем же `request_id` и параметрами возвращает исходный результат. Изменённые параметры с прежним ID дают конфликт. Другое создание с занятым ID не заменяет объект. Неудачная инициализация не оставляет объект или часть его данных; предметный отказ сохраняется для повторов. До фиксации попытка инициализации может повториться после сбоя; после принятого создания повтор и последующая активация её не запускают.
