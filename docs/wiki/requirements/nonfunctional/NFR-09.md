# NFR-09. Проверяемость и независимость модулей

Раздел: [Нефункциональные требования](../../Nonfunctional-Requirements.md).

Каждый модуль имеет отдельную сборку и проверки через общий контракт. Маршрутизация тестируется с заглушками исполнителей и хранения, исполнитель – с локальным адаптером состояния, хранение – с произвольными KV-данными и реальной БД.

Интеграционные проверки запускаются одной командой: загрузка двух типов, атомарность, последовательность, предметный отказ, исключение и таймаут, конкурентные повторы, восстановление и старый владелец. Добавляются перенос, перегрузка, переключение БД и отказ одной VM.

Для ошибок до commit и после commit до ответа предусмотрены воспроизводимые точки отказа. Нагрузочный генератор проверяет итоговые инварианты аукциона и квоты и сопоставляет подтверждённые операции с состоянием. Полный детерминированный симулятор распределённой системы не требуется.

**Приёмка:** команды запуска, конфигурации, отчёты и исходные результаты доступны команде. Пример приложения подключается через публичный API без изменений ядра.
