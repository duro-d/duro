# NFR-08. Журналы

Раздел: [Нефункциональные требования](../../Nonfunctional-Requirements.md).

Для обращения журнал содержит UTC-время, компонент и ID его экземпляра, название операции или метода, длительность и итог. ID объекта, `request_id` и версия кода записываются при наличии; регистрация пакета имеет тип, версию и хеш без ID объекта. Для сохранённого изменения указывается ревизия. Передача объекта между исполнителями записывается отдельно с ID прежнего и нового исполнителей.

Код пакета, аргументы, данные объекта, результаты методов и секреты не попадают в журнал по умолчанию. Секреты не записываются ни в каком режиме.

**Проверка:** по журналам видны смена исполнителя и первый успешный изменяющий RPC-вызов после неё. В них нет тестовых секретов и значений из JSON-аргументов. Отдельная система метрик не требуется. Если позднее реализуется обновление кода, оно также записывается в журнал.

Связанные сценарии: [UC-07](../../Use-Cases.md#uc-07-обновить-код-объекта), [UC-08](../../Use-Cases.md#uc-08-восстановить-обслуживание-после-отказа).
