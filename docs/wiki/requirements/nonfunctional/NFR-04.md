# NFR-04. Лимиты и ограничение ресурсов

Раздел: [Нефункциональные требования](../../Nonfunctional-Requirements.md).

Стартовая конфигурация задаёт следующие лимиты. Их изменение для испытаний записывается в отчёт и применяется одинаково к сравниваемым политикам. Размер JSON измеряется в байтах UTF-8.

| Ресурс | Лимит по умолчанию |
| --- | --- |
| Пакет с манифестом | 1 МиБ |
| Внешний запрос `create/invoke` | 64 КиБ |
| Ключ `storage` | 256 байт |
| Полные KV-данные объекта | 1 МиБ |
| Буфер изменений одного метода | 1 МиБ |
| Результат метода | 64 КиБ |
| Выполнение обработчика до передачи на фиксацию | 1 секунда |
| Ожидающие вызовы одного объекта | 100 |
| Ожидающие вызовы одной ноды | 1000 |

Время ожидания в очереди, активации и фиксации учитывается отдельно в общем deadline запроса. По таймауту поздняя фиксация запрещена; следующий метод получает подтверждённые данные. Конкретный механизм прерывания V8 описывает модуль исполнения.

Кеши кода и состояний имеют конечные бюджеты памяти в конфигурации ноды. Лимиты применяются во время накопления буфера и повторно перед сохранением. Внутренние RPC и ответы чтения должны вмещать допустимое состояние с обёрткой; внешний лимит `invoke` не ограничивает загрузку состояния.

**Проверка:** значения на границе и выше, заполнение очередей, выгрузка неактивных состояний, длительная перегрузка. Память и очереди не растут без ограничения; превышение не оставляет частичных записей.
