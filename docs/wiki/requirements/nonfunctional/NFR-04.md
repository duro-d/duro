# NFR-04. Лимиты

Раздел: [Нефункциональные требования](../../Nonfunctional-Requirements.md).

Базовая конфигурация задаёт следующие ограничения. Размер JSON измеряется в байтах UTF-8.

| Ресурс | Лимит |
| --- | --- |
| Тело входящего HTTP-запроса, включая пакет и манифест при регистрации | 1 МиБ |
| Ключ хранилища | 256 байт |
| Полные пользовательские данные объекта | 100 МиБ |
| Сериализованный буфер подготовленных записей одной команды | 100 МиБ |
| Результат RPC-метода | 64 КиБ |
| Выполнение инициализации или RPC-метода до передачи записей в БД | 1 секунда |
| Ожидающие вызовы одного исполнителя | 100 |

Размеры данных и буфера контролируются во время выполнения и повторно до сохранения. Размер результата проверяется после сериализации и до фиксации. При заполнении очереди новые вызовы не принимаются. Действующие лимиты указаны в конфигурации и документации.

Время выполнения считается от запуска обработчика. Ожидание в очереди, загрузка пакета и данных до запуска обработчика и фиксация в БД в эту секунду не входят; для них задаются отдельные RPC-deadline. При истечении срока подготовленные записи отбрасываются; поздний результат не может быть сохранён. Для PoC допустима кооперативная отмена доверенных обработчиков. Обработчик должен завершаться по сигналу отмены; принудительное прерывание произвольного кода не входит в PoC. Контракт распространяется и на `migrate` при реализации обновления кода.

Лимит входящего HTTP-запроса не применяется к ответам `read`, `readRevision`, `history` и внутренним gRPC-сообщениям. Они должны вмещать максимально допустимые данные или запись журнала вместе со служебной обёрткой. Лимит результата RPC-метода также не ограничивает прямое чтение полного хранилища.

**Проверка:** значения на границе и выше каждого лимита; отсутствие частичных записей при превышении. После таймаута проверяется запрет сохранения позднего результата. Лимиты применяются к созданию, методам, ветке и дополнительным операциям при их реализации. Страница истории вмещает хотя бы одну максимальную запись с обёрткой ответа. Квоты накопленной истории и результатов по объектам не требуются; свободное место в БД контролирует оператор.
