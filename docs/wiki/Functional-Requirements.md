## Общие правила

### Хранилище и завершение метода

`ctx.storage.get/put/delete` работают только с KV-данными текущего объекта. Ключи — строки, значения — JSON. Отсутствующий ключ возвращает `undefined`, сохранённый `null` остаётся `null`. Записи сначала попадают в буфер; метод видит свои изменения. Значения возвращаются копиями, изменение без `put` не сохраняется.

Каждый метод получает один JSON-аргумент; отсутствие входных данных обозначается `null`. Результат — JSON либо `undefined`, который нормализуется в `null`. Платформа ждёт завершения Promise. Неподдерживаемый результат, исключение и таймаут не приводят к частичным записям.

Данные и результат фиксируются атомарно с проверкой владения и исходной ревизии. Успешный вызов с записями создаёт одну новую ревизию; без записей сохраняет только ответ. `ctx.reject(message)` отбрасывает записи и сохраняет предметный отказ без новой ревизии. Внутренняя ошибка завершённым прикладным результатом не становится. После ошибки рабочее состояние сбрасывается до подтверждённого.

Инициализация выполняется через тот же контракт; успешное создание получает ревизию `0`. Предметный отказ создания сохраняется без объекта. При восстановлении успешно созданного объекта `init` повторно не вызывается.

### Повторы

Для `create` и `invoke` клиент задаёт `request_id`. Область уникальности — `(object_id, request_id)`. Результат связан с видом операции и всеми её параметрами; порядок полей JSON-объекта не влияет на сравнение, порядок элементов массива влияет.

Повтор возвращает завершённый результат и его ревизию до нового исполнения. Другие параметры с тем же ID дают `REQUEST_ID_CONFLICT`. Одновременные повторы не приводят к двум фиксациям. Метод до фиксации может выполняться несколько раз. Для нового действия и свежего результата читающего RPC нужен новый ID.

После таймаута исход операции может быть неизвестен. SDK повторяет запрос с прежними параметрами и ID в пределах общего deadline, с задержкой между попытками. Отсутствие ответа не означает отмену или откат. При неопределённом commit модуль состояния подтверждает долговечность результата перед его повторной выдачей.

### Ошибки

Ошибка содержит машинный `code` и сообщение. Завершённый предметный отказ также содержит текущую ревизию; при отказе создания она отсутствует.

| Код | HTTP | Значение |
| --- | --- | --- |
| `INVALID_ARGUMENT` | 400 | Некорректный формат запроса, пакет или значение |
| `UNAUTHORIZED` | 401 | Нет действительного токена |
| `NOT_FOUND` | 404 | Не найден объект, тип, версия или метод |
| `OBJECT_ALREADY_EXISTS` | 409 | ID объекта занят другой операцией создания |
| `CODE_VERSION_CONFLICT` | 409 | Тип и версия зарегистрированы с другим содержимым |
| `REQUEST_ID_CONFLICT` | 409 | ID запроса уже связан с другими параметрами |
| `DOMAIN_REJECTED` | 422 | Предметный отказ через `ctx.reject` |
| `LIMIT_EXCEEDED` | 413 | Превышен размер данных |
| `OVERLOADED` | 503 | Исчерпан допустимый буфер или ресурс приёма |
| `UNAVAILABLE` | 503 | Временная недоступность исполнителя или хранения, в том числе при переносе |
| `EXECUTION_TIMEOUT` | 504 | Истёк срок выполнения обработчика |
| `INTERNAL_ERROR` | 500 | Ошибка исполнения или сериализации |

Технические ошибки допускают повтор с прежним ID; бизнес-отказ возвращается как завершённый результат. Внутренние ошибки не раскрывают стек вызовов и секреты. Недоступная версия кода не подменяется другой.
