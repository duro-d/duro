# Интерфейсы для маршрутизации

Маршрутизатор использует два gRPC-сервиса. У исполнителя он проверяет пакет, запрашивает нагрузку, активирует объект, вызывает метод и готовит перенос. Через сервис состояния читает данные с primary, закрепляет и передаёт владение, разрешает повтор. Условия каждого RPC записаны в [worker.proto](proto/duro/v1/worker.proto) и [placement.proto](proto/duro/v1/placement.proto). Это требования маршрутизации к будущим реализациям. Граница между исполнением и хранилищем остаётся за авторами этих двух модулей. [RFC маршрутизации](https://github.com/duro-d/duro/pull/9) · [Общее согласование](https://github.com/duro-d/duro/issues/2)

## Идентификаторы и результаты

Все запросы наследуют оставшееся время от клиента. После обрыва соединения клиент повторяет изменяющую операцию с теми же параметрами, object_id и request_id. Разные JSON-объекты с одинаковыми значениями полей в другом порядке равны, порядок элементов массива значим. Произвольные JSON-числа сохраняем в исходных UTF-8 байтах. JSON null и пропущенное поле дают разные сообщения. Для полного KV у отсутствующего ключа нет записи в map.

Идентификатор процесса меняется при перезапуске. Первое поколение владельца равно 1. При смене владельца или восстановлении после истечения аренды хранилище выдаёт большее поколение. Время аренды отсчитывает хранилище. Потеря ответа на commit оставляет исход неизвестным, пока хранение не подтвердит состояние. Все RPC маршрутизатора ограничены общим deadline. Один внутренний кадр стенда вмещает до 4 МиБ, включая Protobuf-обёртку. При постраничном чтении сервис состояния сокращает страницу при достижении лимита.

Подтверждённый результат или сохранённый предметный отказ передаются в `OperationResult`. Маршрутизатор возвращает клиенту предметный отказ как DOMAIN_REJECTED (HTTP 422). Для технической ошибки сервер указывает причину в `ErrorDetail` внутри gRPC status.

| Duro code | gRPC | HTTP |
| --- | --- | --- |
| INVALID_ARGUMENT, UNAUTHORIZED, NOT_FOUND | INVALID_ARGUMENT, UNAUTHENTICATED, NOT_FOUND соответственно | 400, 401, 404 |
| OBJECT_ALREADY_EXISTS, CODE_VERSION_CONFLICT, REQUEST_ID_CONFLICT | ALREADY_EXISTS | 409 |
| LIMIT_EXCEEDED, OVERLOADED | RESOURCE_EXHAUSTED | 413 для размера, 503 для нагрузки |
| STALE_OWNER, STALE_CONTROLLER | FAILED_PRECONDITION | обновить маршрут или проверить лидерство, при недоступности 503 |
| UNAVAILABLE | UNAVAILABLE | 503 |
| EXECUTION_TIMEOUT | DEADLINE_EXCEEDED c подтверждённым таймаутом обработчика | 504 |
| INTERNAL_ERROR | INTERNAL | 500 |

## Проверка

Из каталога `api` запусти `go test ./...`. Тест открывает gRPC-соединение с двумя заглушками, проверяет хеш пакета, получение типизированной ошибки и чтение KV. Отдельно проверяет передачу сохранённого null и числа больше 2⁵³.

После изменения Protobuf выполни `buf lint`, `buf generate` и заново запусти Go-тесты. Для генерации использованы Buf 1.68.1, protoc-gen-go 1.36.11 и protoc-gen-go-grpc 1.6.1. Сгенерированные клиенты Go находятся в этом модуле. Проверка других языков и запуск против настоящих сервисов относятся к интеграции.
