# Метрики маршрутизации

Prometheus опрашивает `GET /metrics` на приватном порту каждого маршрутизатора раз в 2 с. Grafana показывает данные на общей временной шкале. Стенд проверяет наблюдаемость маршрутизации по [FR-10](https://github.com/duro-d/duro/wiki/FR-10) и [NFR-08](https://github.com/duro-d/duro/wiki/NFR-08). Данные об исполнителях и состоянии в PoC поступают от заглушек.

## Подключить два маршрутизатора

Сначала запусти [стенд с двумя маршрутизаторами](../README.md#запуск-вручную). На macOS с Docker Desktop или OrbStack Prometheus обращается к приватным портам 18081 и 18082 через `host.docker.internal`. Запусти наблюдение из корня репозитория.

```sh
cd routing/observability
docker compose up -d
```

Если у стенда другие адреса, передай файл с адресами, доступными из контейнера Prometheus. На Linux с Docker Engine узнай адрес шлюза локального моста и укажи его в `-private-listen` обоих маршрутизаторов. В примере адрес моста `172.17.0.1`. Подставь адрес своего моста в файл целей.

```sh
docker network inspect bridge --format '{{(index .IPAM.Config 0).Gateway}}'
cat > /tmp/duro-prometheus-targets.yml <<'YAML'
- targets:
    - 172.17.0.1:18081
    - 172.17.0.1:18082
YAML
DURO_TARGETS_FILE=/tmp/duro-prometheus-targets.yml docker compose up -d
```

На странице [Prometheus Targets](http://127.0.0.1:19090/targets) обе цели должны иметь состояние `UP`. Если заняты порты наблюдения, задай `DURO_PROMETHEUS_PORT` и `DURO_GRAFANA_PORT` при запуске Compose. По умолчанию [дашборд маршрутизации](http://127.0.0.1:13000/d/duro-routing-poc) открывается локально с правами на просмотр.

## Проверить показания

Начни наблюдение до подачи нагрузки. Графики скорости и перцентилей используют окно в 30 с. Дай маршрутизаторам принять серию однотипных вызовов при работающем сборе.

- На графике попыток учитывается каждый завершившийся HTTP-запрос к API, включая повтор с тем же `request_id`. Линия OK показывает ответы с кодом `OK`. Для проверки уникальных клиентских операций и их задержки нужны измерения клиента.
- После отказа исполнителя сопоставь коды HTTP с задержкой исходящих gRPC, устаревшими маршрутами и восстановлениями. Если меняется лидер, значение 1 переходит к другому экземпляру. Состояние сбора показывает доступность самого маршрутизатора для Prometheus.
- При перекосе нагрузки расходятся минимум и максимум очереди или занятости. Лидер публикует границы по исполнителям со свежими выборками. Если таких выборок нет, на графике остаётся пробел. Заглушка возвращает нулевую глубину очереди. Перекос в PoC виден по доле занятого времени. Перенос конкретного объекта можно найти по `object_id` и `epoch` в JSON-журнале маршрутизатора.

Для остановки выполни `docker compose down`. Именованный том Prometheus сохраняет историю для следующего запуска. Команда `docker compose down -v` удаляет и историю этого стенда.
